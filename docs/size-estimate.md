# Оценка объёма проекта

Обновлённая на 2026-10-10 оценка всех этапов: **150–220 тысяч строк исходного кода**,
включая самостоятельные тесты, но без зависимостей, сборки, документации,
lockfiles и сгенерированных файлов. Это диапазон планирования, а не обещание
точного размера и не цель, ради которой нужно увеличивать код.

Текущий срез содержит **116 242 строки исходников**, включая тесты: 110 616 Rust,
3 841 SDK и 1 785 Python-проверок. Остаётся ориентировочно **34–104 тысячи строк**.
Прежняя нижняя граница130 тысяч оставляла около14 тысяч строк: этого недостаточно
для ещё открытых панели, Kotlin SDK, realtime, серверного файлового API, signup,
ролей/политик и проверок обновления, нагрузки и безопасности вместе с тестами.
Поэтому прежние130–200 тысяч теперь исторический ориентир. Самостоятельные
нативные объектные файлы, архивы/restore и ограниченная запись уже реализованы;
это ещё не полноценный пользовательский файловый сервис.

Это не процент готовности и не оценка времени. Сложность интеграции, обнаруженные
ошибки и критерии сохранности важнее количества строк; границы будут уточняться
после следующих сквозных сценариев и проверок. Реальные пользовательские данные
пока не разрешены.

Первоначальная детализация оценки80–160 тысяч сохранена ниже как история,
а не как сумма нового диапазона:

| Компонент | Оценка строк |
| --- | ---: |
| Хранилище, WAL, B+ tree, транзакции | 20 000–40 000 |
| Каталог, SQL, планирование, выполнение | 12 000–25 000 |
| Сервер, проекты, auth, политики, realtime, файлы, backup, CLI | 15 000–30 000 |
| Веб-панель | 12 000–22 000 |
| TypeScript и Kotlin SDK, конвертер | 4 000–10 000 |
| Отдельные интеграционные, crash, property, fuzz и нагрузочные тесты | 15 000–30 000 |

Базовые модульные тесты входят в оценки компонентов; последняя строка относится
к отдельным проверкам всей системы. Верхняя граница растёт при сложном SQL,
MVCC, переносимости на другие ОС и глубокой матрице восстановления. Полная
совместимость с PostgreSQL в эту оценку не входит. Оценку нужно пересматривать
после работающих транзакций, SQL и первого сквозного backend-сценария.

Для коммитов считаются физические строки исходников, включая пустые строки и тесты.
Rust, TypeScript/JavaScript и код внешних тестов считаются отдельно; конфигурация,
документы, зависимости и сгенерированные файлы исключены.
Ориентир — около 1000 новых строк на проверенный логический блок; исправления
и необходимые документы входят в тот же блок. Число строк не заменяет критерии
приёмки и не доказывает готовность к реальным данным.
